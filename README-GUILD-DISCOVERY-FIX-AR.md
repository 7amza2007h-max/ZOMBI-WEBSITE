# ZOMBI — إصلاح نهائي لاكتشاف سيرفرات البوت من Gateway

## لماذا استمرت الرسالة بعد وصول Heartbeat؟

فحص `/health` أثبت وصول Heartbeat حديثًا وفيه 9 سيرفرات. لكن Middleware في Dashboard كانت تعيد إرسال طلب Discord REST منفصل إلى `/guilds/:id` لكل سيرفر لمجرد التأكد من عضوية البوت. عند تعطل REST أو حدوث Rate Limit كانت كل السيرفرات تفشل رغم أن Gateway أرسل القائمة الصحيحة، فتظهر رسالة تعذر التحقق.

## ما الذي تغير؟

- `index.js`: يرسل البوت مع Heartbeat قائمة Gateway الفعلية، ومعها الاسم والأيقونة وعدد الأعضاء ومعرّف المالك لكل سيرفر.
- `server.js`: يحفظ بيانات السيرفرات المسموح بها بعد التحقق من مفتاح Bot Sync الحالي، ويستخدم Heartbeat الموثوق مباشرةً دون طلب REST لكل سيرفر.
- `server.js`: يستخدم البيانات الوصفية المرسلة من Gateway لعرض أسماء السيرفرات في Dashboard وOwner Panel، ويجمع سيرفرات Heartbeat مع السيرفرات التي لها إعدادات محفوظة.
- `server.js`: يحتفظ بآخر قائمة سليمة عند انقطاع Heartbeat مؤقتًا. وعند عدم وجود Heartbeat موثوق لا يعتبر غياب البيانات قائمة فارغة.
- لم يتم تغيير تسجيل الدخول أو قاعدة البيانات أو الصلاحيات الفعلية للأعضاء. بيانات `permissions` في قائمة Owner تبقى محايدة (`0`)؛ وصول Owner يعتمد على جلسة Owner الحالية، وليس على صلاحيات عضو Discord اصطناعية.
- يرسل البوت تحديثًا فوريًا عند `guildCreate` و`guildDelete` بالإضافة إلى التحديث الدوري كل 60 ثانية.

## التركيب على Render

1. استبدل `server.js` في خدمة Dashboard بهذا الملف.
2. استبدل `index.js` في خدمة البوت بهذا الملف.
3. أبقِ متغير `DASHBOARD_URL` في خدمة البوت كما هو، ويشير إلى `https://zombi-90hp.onrender.com`.
4. أبقِ `BOT_TOKEN` في خدمة Dashboard مطابقًا لقيمة `TOKEN` في خدمة البوت. لا تضع أي Token داخل الملفات.
5. أعد نشر الخدمتين. لا حاجة إلى تغيير قاعدة البيانات أو متغيرات OAuth2 أو `discordProxy`.

## الاختبارات المنفذة محليًا

- `node --check server.js` — نجح.
- `node --check index.js` — نجح.
- `npm run check` — نجح على ملفات JavaScript التي يغطيها سكربت المشروع.
- فحص ثابت لمسار Heartbeat: تأكد من أن المسار الموثوق لا يستدعي `getBotGuild()` لكل سيرفر، وأن البيانات الوصفية تصل إلى Owner Panel — نجح.

لم يتم الاتصال بخدمات Render أو Discord الإنتاجية من بيئة التطوير؛ لذلك يجب تأكيد النتيجة بعد النشر من `/health` ومن صفحة Dashboard. المتوقع بقاء `guildCount: 9` (أو العدد الفعلي الحالي)، مع اختفاء طلبات REST التسعة من مسار اكتشاف القائمة.
