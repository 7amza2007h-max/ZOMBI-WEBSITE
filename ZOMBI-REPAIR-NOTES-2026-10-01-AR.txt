ZOMBI — إصلاح شامل للنسخة المرفوعة 2026-10-01

أهم الأخطاء التي تم العثور عليها وإصلاحها:
1) ملف البوت المرفوع لم يكن يحتوي package.json بجانب index.js، لذلك النسخة النظيفة لا تستطيع الإقلاع كما يجب.
   - تمت إضافة package.json صحيح في جذر البوت.

2) index.js كان يطلب ملفات غير موجودة في النسخة المرفوعة:
   - nameChangeSystem.js
   - zomStore.js
   - staffSystems.js
   - warnings.js
   تمت إضافة طبقات توافق مرتبطة بالأنظمة الحالية بدل حذف أي نظام.

3) القوانين كانت تقرأ من guildStore المحلي بدل sharedStore المشترك مع الداشبورد.
   هذا يسبب أن القائمة المرسلة من الداشبورد لا تطابق الإعداد الذي يقرأه البوت، فتظهر رسالة أن القسم لم يعد موجودًا.
   - تم تحويل rulesSystem إلى sharedStore.
   - تم إبقاء deferReply مبكرًا حتى لا ينتهي Interaction ويظهر 10062 Unknown interaction.
   - أضيف توافق مع لوحات القوانين القديمة ذات IDs القديمة.

4) حفظ الداشبورد:
   - كان JavaScript يعطل حقول الأقسام الأخرى وقت الحفظ، ما يسبب FormData ناقصة / سباق بين السكربتات والحاجة لأكثر من محاولة.
   - تم جعل الحفظ يعتمد على _settingsSection فقط، بينما السيرفر يحفظ القسم الحالي وحده.
   - لم يعد يتم تعطيل حقول الأقسام الأخرى قبل الحفظ.
   - تمت إضافة منع الضغط المكرر أثناء عملية الحفظ.

5) مخطط إعدادات الداشبورد كان أقدم من مخطط البوت في guildStore.js.
   هذا يمكن أن يسقط إعدادات حديثة مثل الترحيب، Auto Role، القوانين، صور اللوحات، رابط الخط وبعض إعدادات الألعاب.
   - تمت مزامنة guildStore.js مع نسخة البوت الحديثة.
   - public/guildStore.js في الداشبورد أصبح يستخدم نفس Root Store لمنع اختلاف نسختين من الإعدادات.

6) الترحيب وAuto Role:
   - الكود الأساسي موجود ويقرأ الآن نفس الإعداد المحفوظ من الداشبورد بعد إصلاح الحفظ/المخطط.
   - Auto Role يتحقق من Manage Roles وترتيب رتبة البوت.
   - الترحيب يرسل الصورة ثم الرسالة والمنشن والرومات المحددة.

اختبارات تمت على النسخة المعدلة:
- فحص syntax لجميع ملفات البوت المصدرية: 60 ملف JavaScript بدون أخطاء syntax.
- npm run check للبوت: ناجح.
- npm run check للداشبورد: ناجح.
- فحص require لمسار تشغيل index.js: لا توجد ملفات محلية ناقصة بعد الإصلاح.
- Smoke test للبوت: تم تحميل الأنظمة حتى مرحلة Discord login؛ بيئة الفحص لا تملك اتصال Discord لذلك توقف عند DNS فقط.
- Smoke test للداشبورد: اشتغل محليًا و /health رجع ok=true.
- اختبار حفظ متتابع: إعدادات welcome/autoRole/rules/lineUrl بقيت محفوظة بعد تعديل قسم اقتصاد مختلف.

مهم عند الرفع:
- لا تستبدل .env من أي ملف مضغوط. احتفظ بالتوكن وDATABASE_URL الموجودين في الاستضافة.
- package.json و index.js يجب أن يكونا في نفس جذر البوت.
- شغل npm install ثم npm start (أو node index.js).
- البوت والداشبورد يفضّل أن يستخدموا نفس DATABASE_URL.
- إذا لم يكونا على نفس DB، يجب ضبط PUBLIC_BASE_URL في البوت على رابط الداشبورد، مع نفس BOT_TOKEN/TOKEN المستخدم لحماية bot-sync.
- للـ Auto Role: فعّل Server Members Intent في Discord Developer Portal، وأعطِ البوت Manage Roles، وارفع رتبة البوت فوق الرتبة التلقائية.
- للترحيب: البوت يحتاج View Channel + Send Messages + Attach Files في روم الترحيب.

ملف Cloudflare Worker يستخدم ES Module (export default)، لذلك لا يتم فحصه كـ CommonJS بواسطة node --check؛ هذا طبيعي ولا يؤثر على server.js.
