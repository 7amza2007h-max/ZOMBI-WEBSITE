إصلاح إضافي للداشبورد — ZOMBI

الملفات المعدلة فقط:
- server.js
- site/dashboard.js

ما تغير:
1. جميع عمليات Discord API الكتابية تمر عبر طابور واحد وتتعامل مع retry_after عند 429، بدل إعادة الطلب فورًا.
2. تحديث لوحة موجودة يتم عبر PATCH مباشرة دون GET إضافي قبل كل إرسال/تحديث.
3. تمرير نسخة اللوحة الأصلية كخيار احتياطي إذا رفض Discord تنسيق Components V2، مع الحفاظ على الصور والتصميم.
4. إذا كان لدى السيرفر snapshot حديث للقنوات والرتب والإيموجيات، يتم استخدامه مباشرة دون استدعاء Discord إضافي عند تبديل السيرفر.
5. تسريع التنقل المحلي بتخزين قوائم روابط الأقسام وعناصر الصفحات، وعدم تحديث جميع نماذج POST في كل نقرة.
6. تحسين سجلات 429 لتعرض مسار Discord ورمز الخطأ ومدة الانتظار دون تسجيل التوكن.
7. تحديث نسخ ملفات الواجهة لكسر الكاش القديم.

التركيب:
- أوقف الداشبورد.
- خذ نسخة احتياطية.
- استبدل server.js في جذر المشروع وsite/dashboard.js في مجلد site.
- أعد تشغيل الاستضافة واختبر لوحة واحدة أولًا.

الحدود:
- لا يمكن لأي كود تجاوز حد Discord الحقيقي؛ الكود ينتظر retry_after ويمنع إعادة المحاولة السريعة.
- تم فحص الصياغة بـ node --check، لكن لا يمكن إثبات نجاح الإرسال الفعلي دون تشغيله على استضافتك.
